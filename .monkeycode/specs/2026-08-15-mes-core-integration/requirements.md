# MES 核心能力集成需求

## 1. 简介

本需求将现有 BarTenderPrinter 从标签打印工具扩展为手机制造 MES 工位客户端和中心业务服务。交付范围覆盖主数据、订单、号码、生产、包装、四类标签自动作业、称重、写号、质量、返工、出库、归档修复、导入导出、完整 WinForms UI、安全控制、性能验证和端到端验收。

“全部移植复刻”是依据合法取得的静态手册、操作说明、字段定义、界面样例、数据样例和公开协议，在当前 .NET 技术栈中重新实现完整业务能力和可验证结果。新实现采用自主源代码和获准接口，交付制品排除 HASP、Sentinel、商业加密授权组件、来源或授权未知的二进制文件、证书、密钥、生产数据库和生产日志。认证、授权、密码散列、敏感数据保护、输入校验、幂等控制和审计完整性属于必须保留并强化的业务安全机制。

本规格采用一次完整交付口径。每项能力均以可操作 UI、服务契约、持久化、迁移、审计和自动化测试共同完成为验收条件。

## 2. 术语

- **MES 服务**：负责中心业务规则、全局唯一性、工序状态和追溯数据的服务。
- **工位客户端**：现有 BarTenderPrinter 演进后的 Windows 工位应用。
- **生产订单**：指定客户、产品、颜色、数量和生产计划的业务单据。
- **号段**：分配给订单的一组 IMEI、SN、PSN、MSN、箱号或卡板号规则及范围。
- **生产单元**：由 IMEI 或 SN 唯一标识的单台产品。
- **过站**：生产单元在指定工位完成业务校验并记录结果。
- **包装单元**：彩盒、卡通箱或卡板及其包含的下级单元集合。
- **标签类型**：机身标、彩盒标、卡通箱标、卡板标。
- **设备适配器**：电子称、写号工具、打印机等外部设备的隔离接口。
- **幂等键**：标识一次业务意图并用于安全重试的全局唯一键。
- **主数据**：客户、产品、颜色、工厂、产线、工位、工艺路线、不良代码、包装规则、重量规则、模板和设备配置等受版本控制的业务配置。
- **号码生命周期**：号码从导入或生成、校验、保留、分配、写入、占用、冻结、释放、报废到追溯的状态过程。
- **自动作业**：业务事件满足规则后由 MES 服务原子创建并交由工位执行的打印、称重、写号或质量任务。
- **审计链**：通过前序摘要和当前记录摘要连接的追加式审计事件序列。

## 3. 范围与合规边界

1. MES 交付物应依据合法静态资料和样例重新实现可观察的业务行为、数据约束、操作流程和报表结果。
2. MES 交付物应使用项目自主源代码、标准运行库、已获许可依赖和文档化设备协议构建。
3. 发布流水线应扫描并阻止 HASP、Sentinel、商业加密授权组件、未知二进制、私钥、证书、生产数据库和生产日志进入制品。
4. 设备集成应通过公开或经权利人授权的 SDK、CLI、串口协议或本地服务协议实现。
5. 合规清单应记录每项外部依赖的名称、版本、来源、许可证、用途和批准状态。
6. 系统应保留认证、角色授权、密码散列、敏感配置保护、审计完整性和数据脱敏能力。

## 4. 需求

### 需求 1：生产订单管理

**用户故事：** 作为计划人员，我需要维护生产订单，使工位按统一生产目标执行。

#### 验收标准

1. 当计划人员创建订单时，MES 服务应保存订单编号、客户、产品型号、颜色、计划数量和有效期。
2. 当计划人员发布订单时，MES 服务应验证订单字段完整性和订单编号唯一性。
3. 当订单进入生产状态时，工位客户端应显示订单当前状态、计划数量、完成数量和异常数量。
4. 当订单暂停或关闭时，MES 服务应拒绝新的生产过站并返回结构化原因码。
5. 当授权人员变更订单状态时，MES 服务应按 `Draft`、`Released`、`InProduction`、`Suspended`、`Completed`、`Closed` 和 `Archived` 状态机验证转换。
6. 当订单计划数量、产品版本或交付信息发生变更时，MES 服务应创建带生效时间和审批信息的订单修订版本。
7. 当订单达到完成条件时，MES 服务应核对生产数量、包装数量、质量冻结、未决任务和号码差异并返回逐项结果。
8. 当订单关闭或重新打开时，MES 服务应记录原因、审批人、版本和影响对象数量。

### 需求 1A：主数据管理

**用户故事：** 作为系统管理员和工艺人员，我需要维护受控主数据，使所有工位执行相同版本的业务规则。

#### 验收标准

1. 当授权用户维护主数据时，MES 服务应支持客户、产品、颜色、工厂、产线、工位、班次、工艺路线、工序、不良代码、包装规则、重量规则、标签模板和设备配置。
2. 当主数据版本发布时，MES 服务应验证业务键唯一性、引用完整性、生效区间和审批信息。
3. 当工位领取订单时，MES 服务应返回订单绑定的主数据版本快照。
4. 当已生效主数据被修订时，MES 服务应保留历史版本并按业务发生时间解析适用版本。
5. 如果主数据存在循环路线、重叠生效区间或失效引用，MES 服务应拒绝发布并返回字段级差异。
6. 当授权用户停用主数据时，MES 服务应检查活动订单引用并返回影响清单。

### 需求 2：号段与编码规则

**用户故事：** 作为工艺人员，我需要配置号段和编码规则，使生产标识保持唯一且可追溯。

#### 验收标准

1. 当工艺人员配置号段时，MES 服务应支持固定前缀、日期片段、起始值、结束值、步长和校验规则。
2. 当工位申请下一个号码时，MES 服务应以事务方式分配号码并记录订单、工位和操作员。
3. 当同一幂等键重复申请号码时，MES 服务应返回首次分配结果。
4. 如果号段耗尽，MES 服务应停止分配并返回 `NUMBER_RANGE_EXHAUSTED`。
5. 当号码被报废或释放时，MES 服务应保留完整状态变更记录。
6. 当用户导入号码时，MES 服务应验证号码类型、格式、校验位、全局唯一性、号段边界和重复行。
7. 当号码状态变化时，MES 服务应按 `Available`、`Reserved`、`Allocated`、`Written`、`Consumed`、`Frozen`、`Released` 和 `Scrapped` 状态机验证转换。
8. 当号码预留超过配置期限时，MES 服务应创建回收候选任务并要求授权人员确认释放或延期。
9. 当写号、返工或报废影响号码时，MES 服务应维护号码与生产单元、写号任务、订单和原因的双向追溯。
10. 当授权人员执行号码冻结、释放或报废时，MES 服务应记录审批、原因、原状态和目标状态。

### 需求 3：组装过站

**用户故事：** 作为组装操作员，我需要扫描产品并完成工序过站，使系统记录每台产品的生产路径。

#### 验收标准

1. 当操作员扫描 SN 时，MES 服务应验证订单、工艺路线、上一工序和当前工位资格。
2. 当工序通过时，MES 服务应记录生产单元、工序、工位、操作员、时间和结果。
3. 如果上一工序未通过，MES 服务应返回 `PREVIOUS_OPERATION_INCOMPLETE` 和缺失工序。
4. 当相同幂等键重复提交时，MES 服务应返回首次过站结果。
5. 当产品处于返工路线时，MES 服务应按返工路线验证下一工序。

### 需求 4：包装过站与层级绑定

**用户故事：** 作为包装操作员，我需要建立产品、彩盒、卡通箱和卡板的绑定关系，使包装层级完整可追溯。

#### 验收标准

1. 当操作员扫描机身码和彩盒码时，MES 服务应建立一对一绑定并验证产品状态。
2. 当操作员向卡通箱加入彩盒时，MES 服务应验证订单、型号、颜色和箱容量。
3. 当卡通箱达到配置容量时，MES 服务应关闭卡通箱并生成打印作业。
4. 当操作员向卡板加入卡通箱时，MES 服务应验证卡板容量和箱状态。
5. 如果条码已绑定到其他活动包装单元，MES 服务应返回 `PACKAGING_BINDING_CONFLICT`。

### 需求 5：四类标签打印

**用户故事：** 作为包装操作员，我需要打印机身标、彩盒标、卡通箱标和卡板标，使标签内容与生产数据一致。

#### 验收标准

1. 当 MES 服务创建打印作业时，工位客户端应按标签类型、产品和生效版本解析模板。
2. 当工位客户端执行打印时，现有 PrintJobCoordinator 应保存不可变字段快照和提交结果。
3. 当相同幂等键重复提交时，打印作业账本应返回首次执行结果。
4. 当 BarTender 返回未知结果时，打印作业状态应为 `UNCERTAIN` 并进入人工核查队列。
5. 当授权人员执行补打时，系统应记录原作业、原因码、审批记录、模板版本和补打序号。
6. 当生产单元完成指定组装工序时，MES 服务应自动创建机身标作业并保存业务快照。
7. 当机身与彩盒绑定条件满足时，MES 服务应自动创建彩盒标作业并保存业务快照。
8. 当卡通箱达到关闭条件时，MES 服务应自动创建卡通箱标作业并保存业务快照。
9. 当卡板达到关闭条件时，MES 服务应自动创建卡板标作业并保存业务快照。
10. 当相同业务事件被重复处理时，MES 服务应为每一标签类型返回首次创建的自动作业。
11. 当模板字段、业务字段或数据类型存在差异时，工位客户端应阻止提交并展示缺失、多余和类型不匹配字段。
12. 当作业完成、失败或结果未知时，工位客户端应将设备结果和本地账本快照回传中心服务。

### 需求 6：电子称重

**用户故事：** 作为包装操作员，我需要采集彩盒或卡通箱重量，使系统自动验证包装完整性。

#### 验收标准

1. 当电子称输出稳定读数时，设备适配器应返回重量、单位、设备标识和采集时间。
2. 当操作员扫描包装条码时，MES 服务应按产品配置验证重量上下限。
3. 如果重量超出范围，MES 服务应记录失败结果并返回实际值和允许范围。
4. 当串口断开、超时或数据格式异常时，设备适配器应返回结构化设备错误。
5. 当设备进入模拟模式时，系统应在记录和界面中标记模拟数据。
6. 当包装规则要求称重时，MES 服务应在包装关闭前创建称重任务并阻止缺少合格重量的后续标签或出库操作。
7. 当读数在稳定窗口内满足配置波动阈值时，设备适配器应选择稳定窗口的中位数作为最终重量。
8. 当授权人员复称或豁免时，MES 服务应保留原读数、复称读数、原因和审批记录。

### 需求 7：IMEI/SN 写入

**用户故事：** 作为写号工位操作员，我需要将分配号码写入设备并回读校验，使设备标识与 MES 记录一致。

#### 验收标准

1. 当写号工位请求号码时，MES 服务应返回已保留的 IMEI/SN 及写入任务 ID。
2. 当设备适配器执行写入时，适配器应记录工具版本、设备平台、开始时间和结束时间。
3. 当写入完成时，设备适配器应回读号码并与任务快照逐字段比较。
4. 如果写入结果或回读结果不一致，MES 服务应将任务标记为失败并保留诊断码。
5. 当任务结果处于未知状态时，MES 服务应冻结相关号码并进入人工核查队列。
6. 当生产路线到达写号工序时，MES 服务应原子创建写号任务并关联已保留号码和生产单元。
7. 当写号任务失败时，MES 服务应按诊断码决定重试、换机重写、号码冻结或返工处置。
8. 当写号成功回执被重复提交时，MES 服务应返回首次结果并保持号码占用关系唯一。
9. 当写号工具或协议缺少合法授权资料时，设备适配层应保持模拟实现并将真实设备验收项标记为阻塞。

### 需求 8：质量抽检与不良处理

**用户故事：** 作为质量人员，我需要执行 QA/OQC 抽检并记录不良，使质量结果进入产品追溯链。

#### 验收标准

1. 当质量人员创建抽检单时，MES 服务应记录订单、抽样规则、样本和检验项目。
2. 当质量人员提交检验结果时，MES 服务应记录项目结果、不良代码、责任工序和备注。
3. 如果抽检判定失败，MES 服务应冻结相关包装单元并创建处置任务。
4. 当处置完成时，MES 服务应记录放行、返工或报废结论及审批信息。
5. 当订单达到抽样触发条件时，MES 服务应按抽样规则自动创建 QA、OQC、巡检或专项检验任务。
6. 当质量人员领取任务时，MES 服务应锁定样本清单、检验版本和判定标准。
7. 当检验结果满足接收或拒收规则时，MES 服务应计算批次结论并返回计算明细。
8. 当质量任务逾期时，MES 服务应标记逾期状态并通知配置的责任角色。

### 需求 9：返工管理

**用户故事：** 作为生产主管，我需要创建返工任务，使产品按受控路线重新加工。

#### 验收标准

1. 当生产主管创建返工任务时，MES 服务应保存返工原因、目标单元、起始工序和审批人。
2. 当返工任务生效时，MES 服务应生成返工路线并更新目标单元状态。
3. 当返工产品过站时，MES 服务应记录返工任务 ID 和返工序次。
4. 当返工完成时，MES 服务应验证必需工序全部通过并关闭返工任务。
5. 当返工需要拆包时，MES 服务应失效原包装绑定并保留包装关系历史。
6. 当返工需要换号时，MES 服务应冻结原号码并通过号码生命周期分配替代号码。
7. 当返工单关闭时，MES 服务应重新核对质量结论、包装状态、标签状态和号码一致性。

### 需求 10：成品出库

**用户故事：** 作为仓库人员，我需要按出库单扫描卡通箱，使出货数量和产品明细准确。

#### 验收标准

1. 当仓库人员创建或导入出库单时，MES 服务应保存客户、订单、计划数量和交付信息。
2. 当仓库人员扫描卡通箱时，MES 服务应验证箱状态、订单、客户和重复出库状态。
3. 当出库单提交时，MES 服务应以事务方式保存箱明细并更新库存状态。
4. 如果实际数量与计划数量不一致，MES 服务应返回差异明细并保持出库单为待确认状态。
5. 当卡板作为出库扫描单位时，MES 服务应展开并验证所含卡通箱和生产单元。
6. 当出库确认完成时，MES 服务应生成不可变出库快照并更新所有下级单元库存状态。
7. 当授权人员撤销出库时，MES 服务应验证后续业务引用并记录审批、原因和逆向状态变化。

### 需求 11：历史归档与追溯

**用户故事：** 作为审计人员，我需要查询产品完整履历，使每次生产和打印活动可追溯。

#### 验收标准

1. 当用户按 IMEI、SN、箱号、卡板号或订单查询时，MES 服务应返回关联生产履历。
2. 当订单关闭并满足归档条件时，MES 服务应创建不可变归档快照。
3. 当历史记录被业务排除时，系统应保留原始记录和排除审计信息。
4. 当归档校验失败时，系统应保持源数据可查询并创建修复任务。
5. 当修复人员领取归档修复任务时，MES 服务应提供摘要差异、缺失引用和受影响追溯键。
6. 当修复人员提交修复方案时，MES 服务应在独立事务中重建快照并保留修复前后摘要。
7. 当归档修复通过校验时，MES 服务应关闭修复任务并将新归档版本链接到旧归档版本。
8. 当用户查询归档数据时，MES 服务应验证内容摘要并标识当前有效版本。

### 需求 12：身份、权限与审计

**用户故事：** 作为系统管理员，我需要按角色授权操作，使高风险业务经过审批并可审计。

#### 验收标准

1. 当用户登录时，系统应建立包含用户、角色、工位和班次的会话。
2. 当用户执行补打、返工、报废、归档或出库确认时，系统应验证对应权限。
3. 当用户执行状态变更操作时，系统应记录操作人、时间、原因、旧值、新值和关联对象。
4. 当日志包含 IMEI、SN 或设备诊断时，系统应按数据分类规则生成脱敏展示内容。
5. 当用户创建或修改密码时，身份服务应使用带唯一盐值的自适应密码散列算法保存密码验证材料。
6. 当用户连续登录失败达到配置阈值时，身份服务应实施限速和临时锁定并生成安全审计事件。
7. 当会话达到空闲期限、绝对期限或用户被停用时，系统应终止会话并要求重新认证。
8. 当审计事件写入时，审计服务应保存前序摘要、当前摘要、主体、工位、班次、关联 ID 和 UTC 时间。
9. 当审计链校验发现缺口或摘要不一致时，系统应创建完整性告警并冻结受影响归档操作。
10. 当授权审计人员查询安全事件时，系统应按权限返回脱敏记录和审计链校验结果。

### 需求 13：离线与恢复

**用户故事：** 作为工位操作员，我需要在短时网络故障后安全恢复，使业务结果保持唯一。

#### 验收标准

1. 当中心服务不可达时，工位客户端应保留已接收打印作业和设备任务的本地状态。
2. 当连接恢复时，工位客户端应按幂等键查询中心结果并同步本地状态。
3. 当本地结果与中心结果冲突时，系统应进入人工核查队列并保留双方快照。
4. 当离线策略未授权某项业务时，工位客户端应显示 `ONLINE_VALIDATION_REQUIRED`。

### 需求 14：数据导入导出

**用户故事：** 作为业务人员，我需要导入订单或号段并导出查询结果，使现有业务资料可平滑迁移。

#### 验收标准

1. 当用户导入 CSV 或 Excel 时，系统应验证文件类型、大小、列映射和每行数据。
2. 当导入存在错误时，系统应返回行号、字段和错误原因，并保持有效数据为待确认状态。
3. 当用户导出查询结果时，系统应按当前权限和脱敏规则生成文件。
4. 当导入文件通过验证并确认时，系统应以批次方式保存并记录来源摘要。
5. 当用户下载导入模板时，系统应按对象类型和版本生成列名、数据类型、必填项和示例值。
6. 当导入批次确认时，系统应以全有或全无事务保存订单、主数据、号码、质量计划或出库单对象。
7. 当用户导出大量数据时，系统应创建后台导出任务并提供状态、行数、摘要和到期时间。
8. 当导出文件生成时，系统应采用 CSV 或 Excel 规范转义公式前缀、分隔符、引号和换行。

### 需求 15：完整 WinForms 操作界面

**用户故事：** 作为现场和管理用户，我需要在统一 Windows 客户端完成授权业务，使全部能力可操作、可恢复并可审计。

#### 验收标准

1. 当用户登录时，WinForms 客户端应显示当前用户、角色、工位、班次、服务连接和设备连接状态。
2. 当用户进入业务导航时，WinForms 客户端应提供主数据、订单、号码、组装、包装、四类标签、称重、写号、质量、返工、出库、归档修复、导入导出、追溯、审计和系统设置页面。
3. 当角色缺少页面或命令权限时，WinForms 客户端应隐藏对应入口并由中心服务再次执行授权校验。
4. 当用户扫描条码时，当前工位页面应将焦点保持在扫码输入、显示结构化结果并阻止重复提交期间的再次操作。
5. 当长时间操作执行时，WinForms 客户端应显示进度、取消入口和关联 ID，并保持界面消息循环响应。
6. 当服务或设备发生错误时，WinForms 客户端应显示操作员消息、原因码、恢复动作和脱敏诊断详情。
7. 当本地存在待同步、未知结果或人工核查任务时，WinForms 客户端应显示持续可见的数量和处理入口。
8. 当用户关闭存在未保存编辑或未决设备任务的窗口时，WinForms 客户端应展示受影响对象并要求选择保存、放弃编辑或返回处理。
9. 当界面在 100%、125%、150% 和 200% DPI 下显示时，所有核心命令、字段、表格和状态信息应保持可见且可操作。
10. 当用户仅使用键盘和扫码枪操作时，核心工位流程应按可配置 Tab 顺序完成。

### 需求 16：兼容迁移与差距闭环

**用户故事：** 作为产品负责人，我需要逐项核对静态资料和样例，使完整业务能力具有来源和验收证据。

#### 验收标准

1. 当合法静态资料描述业务页面、字段、状态、规则或报表时，需求追踪矩阵应记录来源、目标需求、实现组件和测试证据。
2. 当静态资料与当前实现存在差异时，差距清单应记录业务影响、处置决策、负责人和验收状态。
3. 当某项行为只能由未知二进制观察时，合规清单应将该行为标记为待业务确认并采用合法样例定义预期结果。
4. 当迁移旧数据时，迁移工具应生成源记录数、目标记录数、拒绝记录、字段映射和摘要对账报告。
5. 当全部交付项申请验收时，每项需求应关联至少一个自动化测试或签署的 Windows 设备验收记录。

## 5. 非功能需求

1. MES 服务应对所有状态变更接口执行身份验证、权限验证、输入验证和幂等校验。
2. MES 服务应使用参数化数据库访问和事务边界保护号码分配、过站、包装绑定及出库。
3. 工位客户端应在打印和设备调用前保存任务快照。
4. 系统应使用 UTC 保存时间，并在界面按工厂时区显示。
5. 系统应为敏感配置提供独立的受保护存储入口。
6. 系统应在 100 个并发工位和每分钟 1,000 次状态变更请求的基准负载下持续运行 60 分钟，业务错误率应小于 0.1%。
7. 在基准负载下，订单查询和精确追溯查询的服务端处理时间应达到 P95 小于 800 毫秒，在线过站、号码分配和包装绑定应达到 P95 小于 500 毫秒，P99 小于 1,000 毫秒。
8. 系统应保留可配置期限的在线历史，并支持归档后按追溯键查询。
9. 在 100 万条生产单元、500 万条过站记录和 1000 万条审计事件的数据集下，精确追溯查询应达到 P95 小于 2 秒。
10. WinForms 客户端冷启动到登录界面应在 10 秒内完成，页面切换应在 300 毫秒内提供可见反馈。
11. 批量导入 10 万行 CSV 的验证和暂存应在 5 分钟内完成，峰值内存应小于 1 GiB。
12. 系统应通过 8 小时稳定性测试，工位客户端托管内存相对稳态基线增长应小于 20%。
13. 系统应为服务、数据库、设备和作业队列提供健康状态、指标和关联 ID 日志。
14. 系统应使用支持版本升级的密码散列参数，并在成功登录后升级低强度历史散列。
15. 系统应对审计链和归档摘要执行定时完整性校验并保留校验结果。

## 6. 端到端验收

1. 端到端测试应覆盖“主数据发布 → 订单发布 → 号码导入与分配 → 组装过站 → 自动机身标 → 写号与回读 → 彩盒绑定与称重 → 自动彩盒标 → 封箱与自动箱标 → 封板与自动板标 → 质量任务 → 出库 → 订单关闭 → 归档 → 追溯”的成功链路。
2. 端到端测试应覆盖质量失败、拆包返工、换号、重写、重包、复检和重新放行链路。
3. 端到端测试应覆盖打印结果未知、写号结果未知、服务中断、客户端重启和幂等恢复链路。
4. 端到端测试应覆盖归档摘要损坏检测、修复任务、归档重建和版本追溯链路。
5. 端到端测试应覆盖角色越权、账户锁定、会话到期、审计链校验和敏感数据脱敏链路。
6. Windows 验收应覆盖完整 WinForms 页面、键盘与扫码枪操作、四档 DPI、BarTender、电子称和获准写号工具。
