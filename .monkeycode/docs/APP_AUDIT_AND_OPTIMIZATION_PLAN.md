# 应用全量复核与优化计划

## 复核范围

当前复核覆盖 `BarTenderPrinter` 应用的核心路径：

- 打印流程
- BarTender COM 调用
- 订单管理
- 模板切换
- 数据源锁定、步长、长度
- 本地完整匹配
- 重复校验
- 历史导入与补打印
- 配置保存
- UI 状态同步
- 同类标签打印软件能力对比

## P0 必修复问题

### P0-1 订单唯一键只使用订单号

涉及位置：

- `BarTenderPrinter/OrderManager.cs`

问题：

`PackagingOrder.BuildKey()` 只返回 `OrderNumber`，`Contains()`、`Add()`、`Find()` 都基于该 Key。不同客户、机型、颜色下相同订单号会互相覆盖或查错订单。

影响：

- 订单配置丢失
- 模板配置串单
- 本地校验数据串单
- 错误订单加载
- 错误模板打印

建议：

- 将订单 Key 改为 `{Customer}|{ProductModel}|{Color}|{OrderNumber}` 四元组。
- 或引入持久化 `OrderId`。
- 增加旧订单数据迁移逻辑。

### P0-2 打印前未校验模板完整数据源集合

涉及位置：

- `BarTenderPrinter/MainForm.cs`
- `BarTenderPrinter/BarTenderService.cs`

问题：

当前打印前只校验“传入字段在模板中存在”，没有校验“模板中的全部命名数据源都已配置和赋值”。模板新增字段后，旧配置仍可能继续打印。

影响：

- 漏字段打印
- 模板默认值打印
- 空值打印
- 模板更新后配置失效但未阻止打印

建议：

- 打印前读取模板当前命名数据源集合。
- 与当前启用数据源做双向校验。
- 缺少配置或缺少值时阻止打印并提示字段名。

### P0-3 补打印未按历史模板设置完整校验

涉及位置：

- `BarTenderPrinter/MainForm.cs`

问题：

补打印只在历史记录模板路径等于当前模板路径时执行当前校验。历史模板和当前模板不一致时，会直接使用历史字段调用 BarTender。

影响：

- 旧字段补打
- 模板变化后绕过校验
- 本地完整匹配不生效
- 长度校验不生效
- 补打印误输出

建议：

- 补打印时按历史记录的模板路径和模板 ID 加载对应设置。
- 校验历史字段是否匹配当前模板字段。
- 缺少对应模板设置时要求操作员确认风险。

### P0-4 实物打印成功但历史保存失败后的处理策略不完整

涉及位置：

- `BarTenderPrinter/MainForm.cs`
- `BarTenderPrinter/HistoryManager.cs`

问题：

当前逻辑在历史保存失败时停止自增、清空和设置保存，避免无历史记录时推进状态。但实物标签可能已经出纸，应用状态停留在打印前。

影响：

- 用户重试时可能重复打印同一值
- 历史记录缺失
- 重复校验索引缺失
- 自增状态与实际出纸状态不一致

建议：

- 增加“历史保存失败处理”对话框。
- 让操作员选择：
  - 确认已出纸并推进序列
  - 保留当前状态等待人工处理
- 记录异常日志和待处理状态。

## P1 高优先级问题

### P1-1 本地完整匹配未绑定具体数据源字段

涉及位置：

- `BarTenderPrinter/MainForm.cs`

问题：

导入的本地数据是一个集合，所有字段都共用这个集合校验。若导入的是 IMEI 列，其他字段也会被要求命中 IMEI 集合。

建议：

- 导入校验数据时选择目标数据源字段。
- 保存 `LocalDataTargetField`。
- 打印时只校验绑定字段。

### P1-2 重复校验按模板路径隔离

涉及位置：

- `BarTenderPrinter/HistoryManager.cs`
- `BarTenderPrinter/MainForm.cs`

问题：

重复校验 key 使用 `templateName|templatePath`。模板移动、复制或换路径后，历史防重断链。

建议：

- 引入稳定 `TemplateId`。
- 历史记录保存 `OrderId`、`TemplateId`、当时路径。
- 防重基于稳定 ID，而不是路径。

### P1-3 历史导入到自增锁定字段时状态不同步

涉及位置：

- `BarTenderPrinter/MainForm.cs`

问题：

历史导入会写输入框，但 `AutoIncrementLocked` 字段的 `LockedValue` 不一定同步更新。

建议：

- 历史导入时同步所有锁定字段的内存状态。
- 或禁止导入到已锁字段。

### P1-4 INI 配置保存非原子化

涉及位置：

- `BarTenderPrinter/MainForm.cs`

问题：

`config.ini` 通过多次 `WritePrivateProfileString` 分段写入。异常中断可能产生半更新配置。

建议：

- 迁移为 JSON 配置。
- 使用临时文件和原子替换保存。
- 增加 `.bak` 自动恢复读取。

### P1-5 INI 未保存 `LengthEdited`

涉及位置：

- `BarTenderPrinter/MainForm.cs`

问题：

保存了 `ExpectedLength` 和 `LengthRevision`，但没有保存 `LengthEdited`，单项长度语义可能在重启后丢失。

建议：

- 保存 `LengthEdited`。
- 加载配置时恢复单项长度标记。

### P1-6 CSV 解析逻辑不统一

涉及位置：

- `BarTenderPrinter/MainForm.cs`
- `BarTenderPrinter/HistoryManager.cs`

问题：

历史记录 CSV 解析和本地校验 CSV 解析实现不同，对引号转义支持不一致。

建议：

- 抽取统一 `CsvUtils`。
- 历史导入、历史导出、本地校验导入共用同一解析器。

### P1-7 历史记录大文件性能风险

涉及位置：

- `BarTenderPrinter/HistoryManager.cs`
- `BarTenderPrinter/MainForm.cs`

问题：

历史加载使用 `ReadAllLines`，搜索和展示会线性扫描并重建 `DataTable`。

建议：

- 增加分页。
- 增加索引。
- 后续迁移到 SQLite 或 JSONL。

## 架构重构建议

### R-1 拆分 `MainForm`

问题：

`MainForm` 体积过大，承担 UI、打印、订单、历史、校验、配置等职责。

建议拆分：

- `PrintWorkflow`
- `OrderEditorController`
- `HistoryPresenter`
- `TemplateSessionState`
- `ValidationService`

### R-2 引入 `TemplateSessionState`

目标：

统一模板路径、数据源、校验、长度、打印配置状态，减少隐藏控件和字段变量同时作为状态源。

### R-3 拆出 `PrintWorkflow`

目标：

统一普通打印、补打印、历史写入、状态推进和异常恢复。

### R-4 拆出 `OrderEditorController`

目标：

订单页只负责订单模板设置维护，不直接驱动打印页。

### R-5 拆出 `HistoryPresenter` / `HistoryRepository`

目标：

历史展示、搜索、导入、补打职责分离。

### R-6 引入 `ValidationService`

目标：

统一长度、本地完整匹配、重复校验。

### R-7 引入 `DialogService`

目标：

统一 MessageBox、OpenFileDialog、SaveFileDialog，提升可测试性。

### R-8 引入 `AtomicFileWriter`

目标：

统一 JSON、CSV、配置文件安全写入。

### R-9 引入 `schemaVersion`

目标：

支持订单、模板、历史数据迁移。

### R-10 引入接口注入

目标：

让 BarTender、文件系统、历史存储、订单存储可替换测试。
